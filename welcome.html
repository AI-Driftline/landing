Thanks for buying Driftline Pro. Three steps, and your next workflow run tests your prompts on the replacement models.

1Find your license key

Polar has emailed you a receipt. Your license key is in it, and in the Polar customer portal linked from that email. It starts with DRIFTLINE-.

2Activate it for your GitHub account

From inside any repository of the GitHub account or organization where you want drift tests, run:

npx @aidriftline/driftline activate DRIFTLINE-…

It prints a license code. Save that code as a repository or organization secret named DRIFTLINE_LICENSE_KEY. One key works on up to 3 GitHub accounts or organizations: run activate once in each. You can free a slot in the Polar customer portal.

3Turn on drift tests

In .github/workflows/driftline.yml, give the Driftline step your license code and the API keys of the providers you use:

- uses: AI-Driftline/driftline@v0
  with:
    license-key: ${{ secrets.DRIFTLINE_LICENSE_KEY }}
  env:                       # only the providers you use
    OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
    ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
    GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}

Then list the 5 to 20 prompts your app really sends in .driftline/prompts.yml (example). For the prompts that matter most, add checks such as must_include or same_fields, so a change in meaning is caught and not only a change in wording.

What happens next

Run the workflow (Actions → Driftline → Run workflow) or open a pull request. The job summary shows both answers for every prompt. With fix-pr: true, the verdict also goes into Driftline's fix pull request. Your keys stay in your pipeline: prompts go from your runner straight to your provider.
